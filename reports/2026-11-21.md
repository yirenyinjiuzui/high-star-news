## Where to start today

Choose Jellyfin for a general media library, Navidrome for music, or Audiobookshelf for long-form audio progress. HandBrake prepares compatible video copies; yt-dlp is an optional command-line tool for permitted archiving. Start with one small collection rather than deploying all three servers.

## 1. Jellyfin

Serve your own media to several devices.

### What it does

Jellyfin manages and streams media from a dedicated server to browser and app clients. This repository is the backend; the web interface is a separate project. Official installation and quick-start links are in https://jellyfin.org/docs/ .

### Why we recommend it

Consider it when your existing video collection needs a shared library interface instead of separate folders on each device.

### How it could help you

1. Browse home-video copies from a second device on your local network.
2. Give household users separate access to selected media libraries.

### Who it fits and what to expect

Free GPL-2.0 software without premium feature licenses according to README. Server packages cover major platforms; client support differs. Hardware, disks, electricity and hosting are separate costs. Transcoding can require substantial CPU/GPU resources; direct playback depends on codecs and client compatibility. Fits owned media libraries, not a service that supplies a subscription catalog. Administration and backups remain your responsibility.

### A small first step

In 25–30 minutes, follow the stable-package quick start on a local test server, add a folder with two personal clips and compare browser playback. Inspect whether playback is direct or transcoded. Remote access and a large import can wait.

## 2. Navidrome

Stream a tagged music collection through a browser or compatible client.

### What it does

Navidrome scans music and metadata, provides a browser player, per-user playlists and play counts, and supports Subsonic-compatible clients and on-the-fly transcoding. Installation: https://www.navidrome.org/docs/installation/ .

### Why we recommend it

Useful when you already have music files and want a focused audio library rather than a broader video server.

### How it could help you

1. Check an album's metadata and artwork while browsing it on a second device.
2. Keep separate playlists and favourites for two household listeners.

### Who it fits and what to expect

Free GPL-3.0 software on Linux, macOS, Windows and Docker, including Raspberry Pi binaries. Server storage, bandwidth and optional managed hosting cost resources; client apps may have separate pricing. Metadata quality determines organization, and transcoding adds processing load. Not a source of music rights or a streaming subscription catalog. README warns master can be unstable; use a release.

### A small first step

Spend 20–30 minutes with a release and a test folder containing one album you may use. Check album grouping, play one track and create a playlist. If setup exceeds the window, stop after validating the installation configuration rather than importing everything.

## 3. Audiobookshelf

Keep listening progress with a self-hosted audio library.

### What it does

Audiobookshelf serves audiobooks and podcasts, keeps progress per user across devices, fetches metadata, edits chapters and supports podcast episode downloads. It also offers basic ebook support and metadata backups. Docs: https://audiobookshelf.org/docs .

### Why we recommend it

Consider it for long-form listening where resume position and chapter structure matter more than a general music player.

### How it could help you

1. Resume a personally recorded course audiobook after switching browser devices.
2. Organize an authorized podcast subscription and compare episode metadata and progress.

### Who it fits and what to expect

Free GPL-3.0 server software; hosting, media storage and network use are separate. Use supported server packages/containers and browser/PWA access. Mobile apps are beta; README says the iOS beta is full, so do not rely on immediate iOS enrollment. Directory naming matters, metadata backup is not a complete media backup, and reverse proxies need WebSockets. The Vue frontend is being rewritten to React; development activity does not guarantee UI stability.

### A small first step

Spend 25 minutes on an existing or local test instance: add one authorized book folder, check chapters, play a minute and reopen to verify progress. Inspect backup scope and keep a separate copy of media. Full server deployment may require longer.

## 4. HandBrake

Create a compatible video copy from an existing source.

### What it does

HandBrake transcodes common camera, phone and screen recordings into MP4, MKV or WebM using libraries such as FFmpeg and video encoders. Official documentation: https://handbrake.fr/docs .

### Why we recommend it

A visual alternative when you need to choose conversion settings without writing an FFmpeg command. Evaluate a small output before committing to a long encode.

### How it could help you

1. Make a playback-compatible copy of a personal recording for a target device.
2. Compare a smaller presentation-video copy against the original for text readability.

### Who it fits and what to expect

Free desktop application for Linux, macOS and Windows. Compiled builds are GPLv2; component and graphic licenses differ, as LICENSE explains. Requires processing time, CPU/GPU capability and space for output. Fits conversion, not a full timeline editor or lossless trimming tool. Re-encoding can reduce quality, hardware support varies and protected inputs are not assumed supported. No size or speed improvement is promised.

### A small first step

Use 20–30 minutes on a short non-sensitive source copy: select a target-oriented preset and new output path, encode a small sample, then inspect text, audio sync and playback on the intended device. Keep the original regardless of the test result.

## 5. yt-dlp

Inspect available media formats and download permitted material reproducibly.

### What it does

yt-dlp is a command-line downloader with site extractors, format selection, subtitles, output naming and post-processing options. Its official README and wiki document installation and dependencies: https://github.com/yt-dlp/yt-dlp/wiki/Installation .

### Why we recommend it

Useful for authorized archiving when explicit format and naming choices matter. Site support changes frequently, so one successful download does not establish continuing compatibility.

### How it could help you

1. List formats for a video you own before choosing an archival copy.
2. Save an authorized educational recording with a consistent filename and available subtitles.

### Who it fits and what to expect

Available on Windows, macOS and Linux/BSD; Python use currently requires 3.11+. Source is Unlicense, while bundled executables and dependencies have additional licenses, including GPLv3+ in PyInstaller builds. FFmpeg/ffprobe, yt-dlp-ejs and a supported JavaScript runtime are strongly recommended for full functionality. Needs bandwidth and storage; site changes can break extractors. It does not grant download rights or guarantee DRM-protected content access.

### A small first step

Spend 15–25 minutes on one permitted URL: inspect yt-dlp --help and run yt-dlp --list-formats URL before selecting a small download. Verify filename, duration and audio. Stop if the site or account does not permit access; avoid cookies and account setup during this first trial.
