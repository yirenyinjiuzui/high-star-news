## Where to start today

Choose one API client first: Bruno if you want request collections as local files reviewed in Git, or Hoppscotch if a browser-first interface fits better. xh is the small command-line option for inspecting an individual request. DBeaver addresses a different problem: exploring database tables and SQL results. Reserve mitmproxy for diagnosing traffic in an application you own or are authorized to test. These are options for different tasks, not a stack you need to install together.

## 1. Bruno

Keep reusable API requests in local text files that can travel with your code.

### What it does

Bruno is a desktop API client that stores collections in filesystem folders using the Bru text format. The official README describes Git-based collaboration, offline-only collection storage without built-in cloud sync, and a CLI for running collections in automated workflows. Requests still contact the chosen API: offline storage does not mean network requests happen without a network.

### Why we recommend it

Recommended when an API example should be reviewable and reusable alongside a project. A changed URL or request field can be inspected in a version-control diff instead of being buried in someone's personal client workspace. It is less compelling if you only need to send a single request once.

### How it could help you

1. Save a test service's health and list requests in a small collection, then change one query parameter and inspect exactly which local file changed.
2. Prepare a reproducible bug example using sample data: store the request and expected response notes so a collaborator can reproduce it without copying your real credentials.

### Who it fits and what to expect

Fits people testing APIs and teams comfortable with files or Git; it does not replace knowing the API's authentication and semantics. Downloads support Windows, macOS, and Linux. Repository code is MIT licensed, while the project also sells commercial editions; check the edition for any specific feature. Desktop installation needs disk and memory, and the CLI needs its documented runtime or Docker route. API usage may be billed. Local collections can still leak secrets if committed or shared, and imported request scripts should be reviewed. Avoid assuming another client's imports will preserve every setting.

### A small first step

15–30 minutes after installation: create a new collection outside a sensitive project, save two read-only requests against a service you control, change a harmless parameter, and inspect the Bru files. Add only sanitized examples to version control. Official README: https://github.com/usebruno/bruno/blob/main/readme.md ; license: https://github.com/usebruno/bruno/blob/main/license.md .

## 2. Hoppscotch

Explore HTTP and realtime APIs in a visual client with collections and environments.

### What it does

Hoppscotch offers request construction, formatted response views, collections, environment variables, pre-request scripts, and post-request tests. Its README also describes GraphQL, WebSocket and other realtime interfaces, browser/PWA use, desktop clients, and self-hosting. It helps inspect and organize calls; it does not prove the remote service behaves correctly under load.

### Why we recommend it

Recommended for learning the relationship between method, URL, headers, body, and response without starting with shell syntax. Compared with a local-file workflow, its browser-first and workspace options may fit quick exploration better. Choose it or Bruno according to how you want to store and share requests.

### How it could help you

1. Explore a public demonstration API with non-sensitive data, change a filter, and compare status, response headers, and returned JSON before writing integration code.
2. Store two test environments with different base URLs, reuse the same read-only request, and add a simple status assertion to spot an accidental environment mismatch.

### Who it fits and what to expect

Fits visual learners and API users; less suited to someone needing only a tiny terminal command. Web/PWA and Windows, Linux, macOS desktop clients are documented. The root repository license is MIT, but hosted, enterprise, collaboration, and infrastructure terms must be checked separately; README feature lists do not guarantee identical availability in every edition. Self-hosting takes deployment resources. Browser CORS rules can prevent direct requests; an extension or proxy changes how traffic travels. A proxy or cloud sync can receive request content, so do not assume a web client keeps everything local, and sanitize shared URLs and exported collections.

### A small first step

15–30 minutes: use the official web or desktop option from the README, enter a read-only demonstration endpoint, inspect headers and JSON, save a collection, then export it and check what it contains. Use dummy tokens. If CORS blocks it, read the documented connection options before choosing a proxy. Source: https://github.com/hoppscotch/hoppscotch#readme ; license: https://github.com/hoppscotch/hoppscotch/blob/main/LICENSE .

## 3. DBeaver Community

Inspect database schemas and query results through one desktop workspace.

### What it does

DBeaver is a multi-database desktop tool with a SQL editor, schema browsing, data viewing/editing, diagrams, and data export/import tools. The README separates Community-supported drivers from commercial extensions. This is a client for an existing database, not a database engine or an automatic backup system.

### Why we recommend it

Recommended to make unfamiliar tables and query results easier to inspect across different database systems. The value is seeing structure and data together while you learn or debug SQL. SQL dialects, permissions, and transaction behavior still belong to the connected database.

### How it could help you

1. Open a copy of a small SQLite dataset, inspect column types and relationships, and run a SELECT with a row limit to understand its contents before analysis.
2. Connect a read-only account to a test database, check the rows behind a report, and export a small sanitized result for comparison with a spreadsheet.

### Who it fits and what to expect

Fits people learning SQL or working with databases; unnecessary for someone who only needs to open a plain text file. Desktop distributions target Windows, macOS, and Linux and require Java; the current README says distributions include OpenJDK 25. Community code uses Apache-2.0, while PRO products, some drivers/connectors, AI services, and the database itself can have separate terms or charges. Runtime, drivers, and result grids use disk/RAM, and large queries consume server resources. Table editing and SQL can modify real data; use a copy or read-only credentials for exploration. AI integrations can send schema context to a configured provider; they are not required for the core exercise.

### A small first step

15–30 minutes: choose the official Community download, connect to a noncritical SQLite copy or existing test database, inspect one table, run one SELECT with a dialect-appropriate limit, and export ten sanitized rows. Check the connection and transaction settings before any edits. Official source and downloads: https://github.com/dbeaver/dbeaver#readme .

## 4. mitmproxy

Observe HTTP traffic through a local debugging proxy with terminal and web interfaces.

### What it does

mitmproxy is an interactive SSL/TLS-capable intercepting proxy. The README lists HTTP/1, HTTP/2, and WebSocket support, mitmproxy's console interface, mitmdump for command-line use, and mitmweb for a browser interface. Unlike constructing a standalone API request, this workflow lets you examine the traffic generated by a configured client.

### Why we recommend it

Recommended when your own application sends something different from what you expected and ordinary application logs do not show enough detail. Seeing the actual request and response can help distinguish a client configuration problem from a server error. It adds network setup complexity, so use a normal API client first if that answers the question.

### How it could help you

1. Route only a test client's harmless HTTP request through the proxy and compare its actual URL, headers, and response with the application's intended request.
2. Reproduce an error in an authorized test environment, inspect the response returned to that client, and record a sanitized example for debugging rather than collecting unrelated browsing traffic.

### Who it fits and what to expect

Fits developers comfortable with proxies, TLS trust, and network configuration; not a general speed booster or a way to gain access to another person's traffic. Consult the official installation page for your OS and supported interface; do not assume console and web interfaces have identical platform support. Code is MIT licensed. A local process and storage for captured flows are needed; large sessions consume memory/disk. HTTPS inspection requires an explicitly configured trust setup, and certificate-pinned clients may refuse it. Captures can contain tokens and personal data. Use a dedicated test client and only traffic you own or are authorized to inspect; remove temporary proxy/trust configuration afterward.

### A small first step

15–30 minutes: read the installation guide linked by the official README at https://github.com/mitmproxy/mitmproxy#readme , choose the appropriate interface, and observe a single non-sensitive HTTP request from an explicitly configured test client. Begin without adding an HTTPS interception certificate. Compare the request, close the proxy, and restore the client's settings. Treat HTTPS trust setup as a separate deliberate exercise.

## 5. xh

Construct readable HTTP requests in a small command-line tool, including an offline preview mode.

### What it does

xh implements much of HTTPie's request syntax in Rust, with JSON/form fields, headers, authentication, sessions, formatted output, HTTP/2 support, and translation to curl commands. Its --offline mode constructs a request without sending it. The README also lists missing HTTPie features and the absence of a plugin system; it is not a complete drop-in replacement.

### Why we recommend it

At 8,165 stars, this is today's explicit exception below 10,000. Recent maintenance and a narrow single-binary workflow justify inclusion: it is useful when you want a request you can inspect or paste into a bug report without opening a full workspace. The project claims speed advantages; this report did not benchmark them.

### How it could help you

1. Preview a JSON request with dummy fields offline, checking that strings, numeric JSON values, and query parameters are placed where intended before sending anything.
2. Inspect a read-only development endpoint from a terminal, then generate a curl equivalent to share a sanitized reproduction with someone who uses another client.

### Who it fits and what to expect

Fits terminal users and people learning HTTP syntax; less suited to visual collection management or workflows dependent on HTTPie plugins. Prebuilt binaries cover Windows, macOS, and Linux; source builds need the documented Rust toolchain. Code is MIT licensed, with local binary storage and network access sufficient for basic use; external APIs may charge. Different package builds can have different TLS options. Shell quoting matters, command history can retain secrets, and network requests can change server data. A successful request is not proof that an API is reliable or secure.

### A small first step

15–30 minutes after choosing an official binary/package: run `xh --offline https://example.com/test name=demo count:=2` and inspect the generated request. Next read `xh help`, then try a read-only endpoint you control and inspect the curl translation with `--curl`. Use dummy credentials and explicit HTTPS. Source, syntax, and limitations: https://github.com/ducaale/xh#readme .
