## 1. Actual Budget

Keep a local-first household budget record with optional synchronization.

### What it does

A personal finance application organized around envelope budgeting, with local-only desktop apps and server-based synchronization options. The README links account-management and migration guides.

### Why we recommend it

Recommended as a way to evaluate whether a consistent record-keeping workflow suits you. Software organization does not determine a financial plan or guarantee savings.

### How it could help you

1. Enter fictional transactions and compare two expense categories.
2. Explore a fresh sample budget before considering migration of an existing record.

### Who it fits and what to expect

MIT free application with Windows, macOS and Linux desktop options. Sync/self-hosting adds server, backup and configuration work; managed hosting and optional providers cost separately. No GPU is needed. Not investment advice or a substitute for checking balances. Imports and category mappings need review, and local-first does not eliminate backup needs.

### A small first step

20–30 minutes: follow https://actualbudget.org/docs/getting-started/starting-fresh with a local test budget and five fabricated entries. Check categories and totals manually, close and reopen it, then read backup/export guidance before adding real records.

## 2. Mealie

Put recipes, a meal plan and a shopping list in one web workspace.

### What it does

A self-hosted recipe manager with manual entry and URL import, cookbooks, meal planning and shopping lists. Its API supports integration with other applications, and Docker deployment is documented.

### Why we recommend it

Useful when recipes scattered across pages make planning awkward. Keeping a few repeatable recipes together can help assemble a list, without claiming dietary or nutrition benefits.

### How it could help you

1. Group three familiar recipes into a cookbook for later reference.
2. Plan two meals and inspect ingredient quantities before using the shopping list.

### Who it fits and what to expect

AGPL-3.0 application accessed in a browser; needs a compatible server/container host, persistent storage and backups. Client browsers can be on major desktop/mobile platforms. Hosting, electricity and optional services are separate costs. Not a diet planner or proof of ingredient safety. Imports can miss quantities, and automatic lists require manual checks.

### A small first step

15–25 minutes: explore existing data in the demo linked at https://docs.mealie.io/ without adding private data. If you already have a test instance, add one invented recipe and inspect a two-meal list. Use the first session to assess deployment requirements rather than assuming installation fits within that time.

## 3. linkding

Find saved links through tags, notes and a focused interface.

### What it does

Self-hosted bookmark management with tags, bulk editing, Markdown notes, read-later status, browser extensions and HTML import/export. It can retrieve metadata and offers local or external website-archiving options.

### Why we recommend it

Recommended when browser bookmarks lack the context needed to find a link again. A short note explaining why it was saved may be more valuable than a large unreviewed archive.

### How it could help you

1. Tag public documentation links by project and add a sentence about their relevance.
2. Import a small test bookmark file, then check an exported copy before migrating more.

### Who it fits and what to expect

MIT web application with Docker setup and browser clients on major platforms; server disk and backup administration are required. Managed hosting costs separately. Not a guarantee that a linked page remains accessible. Metadata retrieval and external archiving can contact other services; stored pages take additional space.

### A small first step

15–25 minutes: inspect the demo linked by https://linkding.link/ using only existing data. With a test instance, save three public links with distinct tags and notes, search for one, and export the small test set. Review archiving settings before using confidential URLs.

## 4. wallabag

Save extracted article content for a quieter reading view.

### What it does

A web application that extracts page content for later reading, with browser-extension and mobile-app options linked by the project. It can be self-hosted or used through its separate hosted service.

### Why we recommend it

Consider it when you save an article to read, rather than just save its address. Extraction can reduce page clutter, but should be checked against the source.

### How it could help you

1. Save an openly accessible tutorial for a later focused reading session.
2. Compare an extracted long article with the original headings and images before relying on it.

### Who it fits and what to expect

MIT server application accessed through browsers and supported clients; self-hosting requires the documented web stack, database/storage and backups. Hosted accounts have separate terms and pricing. Not a universal page archiver: dynamic pages, access controls and complex layouts may not extract correctly. Saving an article does not grant redistribution rights.

### A small first step

15–25 minutes: read https://doc.wallabag.org installation requirements and compare hosting choices. If a test instance is already available, save one public article, check three headings and an image against the source, then reopen it. Avoid using a real personal reading library for the first trial.

## 5. Home Assistant

Bring supported home devices and automations into a locally controlled platform.

### What it does

A modular home-automation system with integrations, dashboards and automation documentation. The core repository recommends a Raspberry Pi or local server; actual device support depends on its integration and connection method.

### Why we recommend it

Recommended only when supported devices and a reason to combine them already exist. A single overview can clarify device state; start with observation before automating physical actions.

### How it could help you

1. Inspect supported sensor states together instead of opening several vendor apps.
2. Sketch a simple lighting routine, then verify each device's integration requirements before enabling it.

### Who it fits and what to expect

Apache-2.0 core; needs compatible hardware or a VM/appliance environment, storage, power and ongoing updates. Browser clients work across common platforms. Devices, radios, hosting and optional cloud services cost separately. Local control varies by integration; some require vendor clouds. Not suitable as an unverified safety-critical control system, and automations can act on real devices.

### A small first step

20–30 minutes: use the official demo at https://demo.home-assistant.io to inspect dashboards and states. Read https://www.home-assistant.io/getting-started/ and check compatibility for one device you actually own. Do not buy hardware or enable a real automation for this first evaluation.
