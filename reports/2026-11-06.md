## 1. Espanso

Turn a short trigger into a reusable piece of text in desktop applications.

### What it does

Espanso watches for configured keywords and expands them into text. Official features include dates, images, forms, app-specific rules and optional scripts. Its rules live in files, so a small set of frequently used phrases can be edited and backed up without maintaining a separate web service.

### Why we recommend it

Recommended for text you already type repeatedly. A few explicit triggers are easier to evaluate than a large automation: check whether each expansion is correct in the applications you actually use.

### How it could help you

1. Create a trigger for the structure of a weekly update, then fill in the actual progress and dates before sharing it.
2. Keep a reusable code-comment or document-reference pattern and insert it while moving between an editor and a browser.

### Who it fits and what to expect

Windows, macOS and Linux; the free project uses GPL-3.0. It runs locally and needs an OS-compatible installation, background input access and YAML rules, without a model or GPU. Not ideal if you rarely repeat text or cannot grant input permissions. Input methods and application behavior can affect expansion; Wayland support is experimental. Scripts and shell extensions add their own requirements and behavior.

### A small first step

15–20 minutes after installation: follow https://espanso.org/docs/ and add a harmless :hello trigger with a short replacement to the match file. Test in a text editor and a browser field, then add one date-based expansion. Check punctuation and your input method, and learn how to pause the tool before expanding your library.

## 2. CopyQ

Find and reuse something you copied earlier instead of copying it again.

### What it does

CopyQ stores clipboard entries in configurable tabs and lets you search, edit, tag and paste them. It supports text, HTML, images and other formats, keyboard shortcuts and optional command-line scripting. Saved history is restored on the next launch.

### Why we recommend it

Useful when moving several pieces of information between documents. Searchable history can reduce back-and-forth copying, while named tabs can separate reusable snippets from transient work.

### How it could help you

1. Copy three public reference URLs and short notes from different pages, then find the right one while writing a draft.
2. Keep a tab of harmless sample commands or table headings, edit one entry, and reuse it in a scratch document.

### Who it fits and what to expect

Free GPL-3.0 desktop app for Windows, Linux and macOS; the README currently specifies macOS 13+. Windows offers installer and portable packages. Needs a running background app and storage for retained entries; images increase storage use. Skip it if built-in clipboard history already meets your needs. History can retain secrets you copy: use exclusions and deletion controls, and do not treat it as a password manager. Clipboard integration varies by desktop environment.

### A small first step

15–25 minutes: use the official package linked at https://hluk.github.io/CopyQ/ . Copy three fabricated text items and one small image, search for the second item, paste it into a scratch document, and create a named tab. Delete test history and inspect exclusion settings before retaining normal clipboard activity.

## 3. ShareX

Capture, explain and save a screen result through one configurable workflow.

### What it does

ShareX combines region and window capture, scrolling screenshots, video/GIF recording, annotations, image editing and configurable after-capture tasks. It can save locally, copy results or upload to configured destinations; these actions are choices in the workflow, not interchangeable guarantees of local processing.

### Why we recommend it

Recommended when a plain screenshot needs arrows, numbered steps or a short reproduction clip. A repeatable capture-and-save workflow can make instructions more consistent without assembling images in several programs.

### How it could help you

1. Document a software problem with one annotated screenshot and numbered steps, saving the result locally for review.
2. Record a short demonstration on fabricated data, then inspect whether the clip clearly shows the action and outcome before sharing it.

### Who it fits and what to expect

Free GPL-3.0 Windows desktop application, with installer and portable downloads. No account is required for basic use. Recordings consume disk space and can require recording dependencies; external hosting has separate terms or costs. Not a macOS/Linux capture solution. Many options can overwhelm someone who only needs occasional snips. Review after-capture tasks and destinations; do not assume uploads are disabled. Inspect the final image for unintended visible content.

### A small first step

20–30 minutes: use https://getsharex.com/downloads and configure a region-capture hotkey with local save and image editing. Explicitly disable upload tasks for this exercise. Capture a harmless test window, add two numbered arrows, save it, and reopen the file to verify its content and location. Video can wait until the basic workflow is familiar.

## 4. AutoHotkey

Bind a repeated desktop action to a short, inspectable script.

### What it does

AutoHotkey is a Windows scripting language and runtime for macros and keyboard shortcuts. It can connect hotkeys to actions such as launching programs or sending text and keystrokes. The official repository distinguishes v2 from the no-longer-maintained v1, so examples must match the installed major version.

### Why we recommend it

Recommended when a specific repeated action falls outside a ready-made utility. Start with one hotkey whose effect is easy to see and undo; a short script is easier to inspect than a long chain of timing-dependent clicks.

### How it could help you

1. Create a shortcut that opens your chosen note editor, reducing the steps needed to start a recurring writing session.
2. Use a hotkey in a scratch editor to insert a harmless checklist heading, then decide whether a script offers more value than plain text expansion.

### Who it fits and what to expect

Free GPL-2.0 Windows runtime; no model or GPU is required. README says v2 should run on Windows 7+, but each release is tested only on Windows 11. Choose a stable v2 release rather than treating the repository's alpha branch as the normal download. Requires learning syntax and keeping scripts running. Not suitable for macOS/Linux or unattended workflows that depend on fragile focus and screen coordinates. v1 scripts are not automatically compatible with v2; hotkeys can conflict with existing shortcuts.

### A small first step

15–30 minutes after installing stable v2 from https://www.autohotkey.com/ : follow the official v2 tutorial, create a script declaring #Requires AutoHotkey v2.0, and bind one unused hotkey to a message box. Run it, verify the shortcut, and exit via its tray icon. Add a non-destructive editor action only after that check; avoid multi-step click automation on the first attempt.

## 5. ActivityWatch

Review recorded application activity to understand where a work session went.

### What it does

ActivityWatch stores activity data locally and uses watchers for active applications and window titles, browser tabs and URLs, and keyboard/mouse activity to detect time away. A browser watcher needs its corresponding setup; the dashboard summarizes recorded events rather than understanding the quality or purpose of your work.

### Why we recommend it

Recommended for comparing your impression of a session with a recorded timeline. A short review can reveal frequent switching or a miscategorized app, but time in an application is not a measure of learning, output or productivity.

### How it could help you

1. Record a short reading-and-writing session, compare the timeline with your own notes, and identify one category that needs correction.
2. Review whether repeated switches between a document and browser interrupt a planned block, then try one scheduling change in a later session.

### Who it fits and what to expect

The repository uses MPL-2.0 and lists Windows, macOS, Linux and Android, with no iOS support. Start with the desktop app; platform and watcher coverage vary. The local open-source application is distinct from optional Pro offerings. Needs background watchers, local storage and permissions; no GPU is needed. Not a billing or performance-assessment instrument. Titles and URLs can contain private data, local storage needs protection, and AFK thresholds or unsupported apps can distort totals. Do not assume cross-device sync is turnkey.

### A small first step

20–30 minutes: follow https://docs.activitywatch.net/en/latest/getting-started.html and run the desktop package. Use a 10-minute fabricated task, inspect window and AFK events in the dashboard, correct one category, and learn how to stop watchers and remove test data. Add browser tracking only after reviewing what it records.
