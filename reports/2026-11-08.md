## 1. Polars

Express table transformations as queries that can be inspected and reused.

### What it does

A Rust-based analytical engine with DataFrame and SQL interfaces, expression-based filtering, grouping and joins, lazy query optimization and parallel execution. Python is one supported interface; GPU acceleration is optional.

### Why we recommend it

Try it when repeated CSV/Parquet transformations have outgrown manual spreadsheet edits. Explicit expressions can make the cleaning rules easier to review; speed depends on the workload and is not benchmarked here.

### How it could help you

1. Summarize a public orders table by customer after filtering cancelled rows.
2. Join two small reference tables and inspect missing matches before exporting a cleaned dataset.

### Who it fits and what to expect

MIT local library on compatible Windows, macOS and Linux environments. Needs Python and a suitable binary/CPU, RAM and disk for data; optional GPU or cloud products have separate requirements and costs. Not a drop-in pandas replacement: expressions, null behavior and data types need checking. Larger-than-memory capability does not make every query fit any machine.

### A small first step

20–30 minutes in a fresh environment: follow https://docs.pola.rs/ , load a tiny fabricated table, filter one category and group totals. Repeat using a lazy query, inspect its plan and compare row counts and sums by hand. Scale up only after correctness checks.

## 2. scikit-learn

Build and evaluate a modest baseline before trying a larger model.

### What it does

Provides supervised and unsupervised estimators, preprocessing, pipelines, model selection and evaluation. The official getting-started guide uses a consistent fit/predict interface and demonstrates combining transformations with an estimator.

### Why we recommend it

Recommended for learning a complete baseline workflow, including held-out evaluation, rather than judging a model by training accuracy alone.

### How it could help you

1. Compare a simple classifier with a trivial baseline on a small public dataset.
2. Put scaling and prediction in one pipeline so validation fits preprocessing on training data rather than the full dataset.

### Who it fits and what to expect

BSD-3-Clause library for compatible Python environments on major desktop OSs. The development README currently specifies Python 3.12+ and numerical dependencies; check the chosen stable release separately. CPU/RAM requirements grow with data and estimator; no GPU is required for a small baseline. Not a general deep-learning framework. Leakage, unsuitable splits and biased data can make scores misleading.

### A small first step

20–30 minutes after environment setup: follow https://scikit-learn.org/stable/getting_started.html using a small bundled dataset, a train/test split and one pipeline. Record the split seed and test metric; do not tune repeatedly on the held-out test set. This is a learning example, not evidence of real-world model validity.

## 3. Optuna

Turn a parameter experiment into a bounded, recorded study.

### What it does

An optimization framework with Python-defined search spaces, samplers, pruning and parallel studies. Each trial executes your objective; optional visualization and a separate dashboard help inspect trial histories.

### Why we recommend it

Useful after a meaningful objective and validation strategy already exist. It replaces ad hoc parameter edits with an explicit search budget, but cannot repair a poorly chosen metric.

### How it could help you

1. Search a small model's depth range using the same cross-validation objective.
2. Compare a handful of preprocessing parameters while recording failed and completed trials.

### Who it fits and what to expect

MIT Python library; current README lists Python 3.10–3.15. Runs across supported OS environments. Objective evaluations consume CPU/GPU and time according to your model; storage/dashboard dependencies and cloud compute are additional. Not an accuracy guarantee. Repeated validation optimization can overfit and parallel workers multiply cost.

### A small first step

15–25 minutes: follow https://optuna.readthedocs.io/en/stable/tutorial/ with a cheap quadratic objective and a budget of 20 trials. Inspect best parameters and trial history, then set an explicit timeout before adapting to a model. Keep a final test set outside the search.

## 4. Plotly.py

Share a chart readers can zoom, inspect and filter visually.

### What it does

Python charting built on plotly.js, with graph objects and the higher-level Plotly Express interface. Charts render in compatible notebooks or standalone HTML; static export uses Kaleido and requires Chrome/Chromium.

### Why we recommend it

Recommended when readers need to inspect individual points or change the visible range. Interactive HTML can accompany a written interpretation rather than replacing a clear chart design.

### How it could help you

1. Plot a public time series and zoom into a short interval to inspect a spike.
2. Compare groups in a scatter plot with hover labels, then verify that units and category colors are clear.

### Who it fits and what to expect

MIT code; compatible Python, a supported dataframe library for Express, and a browser/notebook renderer are needed. Works on major desktop OSs; no cloud account needed for local charts. Hosted services have separate terms. Large datasets can overwhelm browser memory. HTML can embed the underlying data; static output loses interaction and needs extra dependencies.

### A small first step

15–25 minutes: follow https://plotly.com/python/ to create a tiny bar or scatter chart. Add axis units, hover labels and a meaningful title; save as standalone HTML with bundled JavaScript and reopen locally. Check whether the shared file contains only data intended for readers.

## 5. Gradio

Wrap a working function in a browser interface for a small demonstration.

### What it does

Interface maps input/output components to a Python function. Blocks supports custom layouts and events, while ChatInterface provides a chat-oriented UI. A local launch serves a browser app; optional share links make it publicly reachable.

### Why we recommend it

Recommended when a collaborator should test a function without editing Python. Start with a deterministic function before adding a model or a remote API.

### How it could help you

1. Let someone vary two harmless numeric inputs and inspect the computed result.
2. Build a small text-cleaning demo to compare input and output on fabricated examples.

### Who it fits and what to expect

Apache-2.0 package; README requires Python 3.10+. A compatible Windows/macOS/Linux Python environment and browser are needed. UI code does not include model weights, GPU resources or API credits. Not a complete production deployment plan. Public sharing changes who can access the app; compute remains on the running host and function errors remain your responsibility.

### A small first step

20–30 minutes: follow https://www.gradio.app/getting-started/ and wrap a greeting or string-length function with Interface. Launch locally without share=True, test empty and long input, and stop the server after review. Add model calls only after checking dependencies and costs.
