## 1. reveal.js

Keep an optional explanation one keystroke away.

### What it does

Nested HTML sections form vertical slide stacks. Left and right move through the main topics, while up and down open supporting slides. Speaker notes can hold cues for each topic.

### Why we recommend it

A speaker can prepare a short route through a talk and still answer a detailed question without hunting through an appendix.

### How it could help you

1. Place a worked example directly below the formula it explains.
2. Keep a measurement method under a results slide for questions about how the number was obtained.

### Who it fits and what to expect

MIT-licensed HTML framework for modern browsers. Local slides can use bundled assets. Budget time for HTML edits and rehearsal of keyboard navigation. PDF handouts flatten the interactive route into pages.

### A small first step

Allow 20 minutes. Make three top-level slides and put one detail slide below the second. Rehearse once using only the right arrow, then repeat and visit the detail. Check which slide appears when you continue right.

## 2. Slidev

Explain a code change in slides you can review alongside the code.

### What it does

Write slides in Markdown with highlighted code blocks. The Vite preview updates as you edit, and Vue components can add interaction where an example needs it.

### Why we recommend it

A small change to a code example is easy to locate in a text diff before a workshop.

### How it could help you

1. Step through two versions of a function while highlighting the changed lines.
2. Let learners vary an input in a Vue component and inspect the result on the slide.

### Who it fits and what to expect

MIT-licensed. Use the online starter or a local Node.js environment meeting the README requirements. Themes and components add dependencies. Interactive controls need the browser version during a talk, so inspect static exports separately.

### A small first step

Allow 20 minutes. Open the official starter, make a two-slide explanation of a small function and highlight the line that changes its result. Edit that line and check both the browser preview and the exported page for readability.

## 3. asciinema

Replay a command-line demonstration at the audience’s pace.

### What it does

The CLI records terminal output and timing into an asciicast file. The player supports pausing, changing speed and limiting idle time. A separate web player can embed the recording in a page.

### Why we recommend it

A rehearsal becomes a reusable teaching example when rebuilding the same terminal state during a talk would take too long.

### How it could help you

1. Pause a recorded test run at the first failing assertion and ask the audience to interpret it.
2. Replay a short text-processing pipeline and skip the idle time between commands.

### Who it fits and what to expect

GPL-3.0 CLI for GNU/Linux, macOS and FreeBSD. Local recording and playback need a terminal and storage for the cast file. Graphical application windows require another capture method. Anything printed to the terminal becomes part of the recording.

### A small first step

Allow 15 minutes in a sample directory. Run `asciinema rec demo.cast`, display a short sample text file and count its lines, then exit the recording shell. Replay with `asciinema play demo.cast` and pause where the count appears.

## 4. presenterm

Present a Markdown deck directly in a terminal window.

### What it does

The presenter reads Markdown, highlights code and can reveal selected lines in stages. Changes to the source can reload the presentation during rehearsal.

### Why we recommend it

Included below the usual star threshold because it lets a terminal workshop use the same window dimensions and typography for both slides and shell examples.

### How it could help you

1. Walk through a configuration file a few lines at a time.
2. Rehearse a workshop at the terminal width available on the classroom projector.

### Who it fits and what to expect

BSD-2-Clause software with packages for multiple desktop platforms, including Windows. Text and code need a terminal. Images, font sizing and animations depend on terminal capabilities, so a graphics-heavy talk needs a rehearsal on the actual display.

### A small first step

Allow 15–20 minutes. Adapt the project’s demo Markdown into two short slides with one code block. Open the deck at projector width, increase the terminal font and shorten any line that wraps away from its explanation.

## 5. impress.js

Move from a map of an idea into one of its details.

### What it does

Place HTML steps at chosen coordinates and scales. CSS transforms move the viewport between those steps, so the same layout can show a close-up and an overview.

### Why we recommend it

It suits explanations in which relative position carries meaning, such as a floor plan with three stations.

### How it could help you

1. Follow a visitor’s route through a small exhibition, zooming in on each stop.
2. Return to an overview after exploring one subsystem so the audience can locate it again.

### Who it fits and what to expect

MIT-licensed framework for modern browsers. You supply HTML, CSS and the layout coordinates. Long transitions or frequent rotation can make text harder to follow. A linear talk with little spatial information gains less from the setup.

### A small first step

Allow 25 minutes. Adapt the official example into an overview and two close-ups of adjacent stations. Remove rotation, set the destination labels clearly, and check whether a viewer can point to both stops when you return to the overview.
